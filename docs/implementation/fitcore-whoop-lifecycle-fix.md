Physical iPhone evidence from the user: measurements disappear after app switching and complete close/reopen. #304 only retained evidence across transient refresh failures, not lifecycle transitions. This branch fixes the existing coordinator; no general audit.

- Hidden transitions fence/cancel pending reads without resetting the authorized RAM snapshot, version, original expiry or cooldown. Expiry timers remain armed, and snapshot reads enforce the original deadline even if iOS suspends timers.
- Visibility and network availability are separate. Offline disables network operations, not authorized evidence. Return/online triggers revalidation and automatic refresh under the existing cooldown/Retry-After policy.
- Cold startup requests the authenticated server `/records` snapshot concurrently with status; it does not wait for fresh WHOOP synchronization to display existing authorized server data. Each records response now includes the current connection/event revision from the same SQL read. Stale revision replies cannot overwrite newer authorization; one bounded records reread restores the current snapshot.
- Confirmed locked/disconnected/disconnecting/reconnect-required responses, 401/403, explicit invalidation and expiry clear protected data. Temporary network/status/decode errors do not revoke an existing lease.
- No browser caching or local/session-storage persistence added. All transports remain no-store. Server cache permission flags, provider freshness/retention deadlines, session lifetime and durable-cache settings remain unchanged. If the server has no authorized reusable snapshot (including live-only/no-store mode), cold startup must obtain fresh data; expired data is never fabricated or extended to cover that gap.
