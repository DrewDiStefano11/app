## Score rules

WHOOP Recovery must be scored, non-calibrating, finite 0–100, no more than 48 hours old, non-future, and inside a currently authorized unexpired snapshot. A current pending/calibrating WHOOP recovery is displayed as unavailable rather than silently replaced by an older recovery or manual estimate. Source/date is visible beside the existing value.

With eligible WHOOP Recovery W and recent (48-hour) confirmed subjective check-ins, C is their mean existing check-in score: `(energy + motivation + (11-soreness) + (11-stress)) / 40 * 100`. Readiness = `round(0.70 W + 0.30 C)`. Both are required for this model; neither raw HRV, resting HR, sleep duration nor sleep performance is counted again. This is a transparent FitCore heuristic, not a clinical model or a recreation of WHOOP Recovery. If WHOOP is absent, the existing recorded sleep/check-in estimate remains explicitly FitCore-labelled. Training-load evidence remains in its existing separate analysis; it is not injected again into the measured WHOOP Recovery.

FitCore Score retains `round(.35 Training + .25 Nutrition + .25 selected Recovery + .15 Progress)`. Training, Nutrition and Progress must still meet their existing support thresholds. No renormalization fills missing components. Every snapshot update/expiry/lock invalidates derived WHOOP contributions immediately; nothing is saved to tracking state or backups.

Momentum remains a distinct existing activity summary: at least two supported factors are required, with Training/Nutrition/Recovery/Progress weights 35/25/25/15 normalized over the supported contributors. Its Recovery factor now uses the same authoritative selection, avoiding a competing manual Recovery value in its detail sheet. When WHOOP contributes, its label is Activity & recovery. This partial-factor summary does not change the all-four requirement for FitCore Score. Calls used to build AI context still receive no WHOOP snapshot, preserving the separate consent boundary.

The Readiness history uses the same formula and 48-hour as-of window for each observed day. Today's endpoint uses the current cutoff and matches the headline; earlier days with no observations keep gaps. Historical source selection validates the current authorization window before selecting records as of each prior cutoff. Demo mode never combines its fabricated tracking records with actual WHOOP evidence and suspends automatic WHOOP sync. Manual Recovery fallback is explicitly labelled FitCore estimate. Measured Recovery renders its original numeric value and percent unit directly, without an intermediate animated/rounded score.

Last sleep selects across all eligible dated observations, while the seven-day chart/average use only the seven local calendar nights ending today. A completed WHOOP main sleep can replace the duration selected for a night without removing that night's independently recorded manual quality rating. Unfinished, pending, calibrating, nap and incomplete-stage sessions never supply a fabricated nightly duration.

## Refresh design and root cause

The old route effect set nextAttempt after a 200/204 but armed another timer only after 409 or a later lifecycle event. The dashboard's independent 120-second read poll could clear expired transient records but could not renew them. A visible app therefore stopped renewing after its initial sync.

Use one memory-only browser evidence store plus one lifecycle-aware coordinator. A pure injectable scheduler owns eligibility, recurring timers and one in-flight sync. The existing manual request API joins that same in-flight request. A React useSyncExternalStore hook exposes one snapshot to Home, Recovery, score hooks and details. Components do not independently poll or fetch.

After every success (200 with live body or 204 followed by authenticated records read) or recoverable failure, arm the next eligible request. Refresh toward snapshot expiration, bounded by the server's two-minute cooldown and Retry-After (seconds or HTTP date). Clear at the actual permitted deadline even when refresh is cooling down or delayed. Expiration clears display; it does not terminate an authorized renewal loop. 401/403 or locked/disconnected/unavailable status stops renewals. Successful unlock/reconnection can restart eligibility checks. Hide/offline cancels timers, clears sensitive display on hide, and fences late results; resume/focus/pageshow/online revalidates status and rechecks time. Do not issue overlapping manual/automatic requests or propagate measurements through BroadcastChannel/localStorage.

Each status, sync and protected-record read/body has a fenced 60-second deadline even if transport ignores abort. Retry-After from status and records is preserved across focus/hide/resume. A protected read failure after 204 is returned to the manual caller rather than reported as successful synchronization. Already-permitted cached records can be restored after foreground authorization or a 409; visible status/sync cadence remains bounded to two minutes even when a cache's display expiry is much later. These paths do not enable durable caching, background work or additional permissions.
